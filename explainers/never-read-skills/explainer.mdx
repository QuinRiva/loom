## 2. How dropping works

There are three switches, each already used somewhere in your setup. A change to `~/.pi/agent/settings.json` reaches every loom thread on its next turn, because loom starts a fresh pi for each run; a change to pi-craft or pi-fathom goes through a PR in that repo (both are agent-merged) and lands when the checkout is pulled.

### Switch off a package's skills, keep its tools

In `~/.pi/agent/settings.json`, a package written as an object can filter what it loads; `"skills": []` loads none of its skills and leaves its extension (its tools) alone. Your `my-pi-setup` entry already does exactly this. For `librarian` and `session-history`:

```json
// before
"npm:pi-web-access",
"npm:pi-session-search",

// after
{ "source": "npm:pi-web-access", "skills": [] },
{ "source": "npm:pi-session-search", "skills": [] },
```

For `pi-intercom` and `pi-prompt-template-model`, where neither the tool nor the skill is used, deleting the line (and `pi remove` to uninstall) is the cleaner end state; `"skills": []` is the fallback if you want the tool kept.

### Hide a skill but keep it callable

`disable-model-invocation: true` in a skill's frontmatter takes it out of the catalogue the model sees, while `/skill:name` still works and other skills can still read it by path. `wayfinder` and `grill-me` already carry this line. This is the right switch for `domain-modeling` and `prototype`.

### Delete or move the folder

pi-craft's `package.json` points pi at `./plugins/pi-craft/skills` and pi finds every `SKILL.md` beneath it, so the folder is the switch: delete it and the skill is gone; move it to `pi-fathom/plugins/pi-fathom/skills/` and it loads only in fathom-platform checkouts, the scoping that went live on 23 October. Git history keeps a deleted skill recoverable.

- **`wayfinder` itself** (hidden, about 2,300 words) is outside this batch. If you decide you will not use it, `domain-modeling` and `prototype` can be deleted with it rather than hidden.
