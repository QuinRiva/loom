2 · Proposed information hierarchy

  1. Where is the live front / what needs me? — pre-attentive: card colour, attention pulse, terminal recession. (Already works well.)
  2. What is this node? — the title. Currently the most-starved element despite being the only thing that distinguishes siblings.
  3. What state is it in, named? — one worded state (reworking ⟲1, blocked, done). The 8-lane palette (slate/indigo/cyan/steel/sky/violet/emerald/slate) exceeds reliable at-a-glance hue discrimination, so one word confirms what the colour suggests.
  4. Coarse progress — ⚒ tools · age, for live nodes only.
  5. Everything else — purpose, model, cost, gate history, fork/fan-in/consult detail → the hover card and context menu (both already exist and are good).

Guiding rule: each fact gets exactly one on-node encoding, plus at most one pre-attentive channel (colour) for the two facts that must be scannable across 30 nodes: status and attention.

3 · Options per slot

3a · Title (identity)

Option Pros Cons
T1 — two-line wrap, full card width recommended ~24 chars × 2 lines ≈ 48 chars — nearly every ≤6-word title fits whole; fixed node size keeps columns aligned; no layout-algorithm change SVG has no native wrapping — needs a small tspan line-breaker (char-count heuristic is fine at a fixed width)
T2 — dynamic node width to fit the title Every title complete on one line Ragged columns break the band layout's rhythm; long titles blow node density in the constrained horizontal axis; layout code assumes NODE_W in several places
T3 — keep one line, reclaim the 43px indent + widen to ~180 Trivial diff Still only ~26 chars; mid-string distinguishing tokens still lost
T4 — middle-ellipsis truncation (keep head + tail) Preserves distinguishing tail tokens cheaply Ugly; still guesswork about which tokens matter

3b · Status

Option Pros Cons
S1 — stroke + fill colour, plus one worded state; delete the dot recommended Keeps the pre-attentive scan; the word disambiguates the 8-lane palette (steel-blocked vs slate-planned vs cyan-ready are close); removes the pure-redundancy dot None material — the dot carries zero unique information
S2 — colour only (delete dot and status word) Maximum space for title 8 hues are not reliably distinguishable even for normal colour vision; forces legend round-trips for the cooler states
S3 — left accent bar (like board cards) on a neutral card Quieter canvas; status still scannable Loses the fill-tint glow that makes the live front pop against receded terminals — the graph's best current feature

3c · Role

Option Pros Cons
R1 — word only (coder, reviewer); delete the glyph recommended Words are read, not learned; open-ended roles make any glyph map incomplete; frees 30px Slightly less "iconic" at extreme zoom-out — but the glyphs were never legible there either
R2 — real icons (lucide wrench/eye/search/map) + word Genuinely distinct silhouettes, unlike ◎/◇/✦ Still redundant with the word; open-ended roles still need a fallback; adds icon-path plumbing into SVG
R3 — drop from the node entirely (hover card has it) Most minimal Coder-vs-reviewer at a glance is genuinely useful when scanning gate pairs; costs little to keep as one word

3d · Gate / review-loop story (the worst redundancy)

Option Pros Cons
G1 — the state word absorbs the gate leg: state reads reworking ⟲1 / waiting on rework; delete both straddling pills; edge keeps badge ⟲1/2 + verdict tint; reviewer keeps only its verdict chip recommended The gate leg is the node's state, so it belongs in the state slot — from 4 encodings down to: node state word, edge badge (rounds/cap), verdict chip (the human-relevant judgement). Pills stop colliding above/below cards Rounds/cap detail moves one step away (edge badge or hover); state words get longer than lane labels
G2 — node owns it: keep pills, delete the edge badge All info on the card Pills straddle borders and collide with neighbours (visible in the screenshot); loop count is naturally an edge property
G3 — edge owns everything: no gate text on nodes at all Cleanest cards "Why is this coder sky-coloured but idle?" becomes unanswerable without hovering; verdict is genuinely card-worthy

3e · Progress footer (⚒ tools · age)

Option Pros Cons
F1 — fold into the meta/state line, right-aligned; pulse dot stays as the single liveness animation Frees a band; two-band card stays 66px tall Meta line is busier; long role names crowd it
F2 — keep a dedicated metrics band fits design C No crowding; vertical space is the unconstrained axis, so the extra band is cheap Slightly taller card
F3 — drop from node (hover card has both) Simplest card "Is it actually doing something?" is a scan-level question; tools+age is the cheapest honest signal of motion

6 · Recommendation

Design C2 — header-band card with the full-card status tint kept. Per slot: T1 two-line wrapped title in the body · S1 colour + one state word (in the header strip), dot deleted · R1 role as a word in the strip, glyphs deleted (ROLE_ICONS goes away) · G1 gate leg folded into the state word, gate-wait pill deleted, verdict chip kept on the reviewer, rounds/cap stays on the edge badge · F2 dedicated metrics band (⚒ tools · age), since vertical space is cheap.

Corner badges (⑂ fork, fan-in, consult count) stay as-is — they encode relationships with no other on-node home and don't compete with the title. The hover card and context menu are unchanged; they remain the drill-down for purpose, model, cost, and gate history.

Fallback if the strip geometry feels heavy in practice: Design B delivers the same information diet in two bands at the original height, at the cost of a denser meta line.
