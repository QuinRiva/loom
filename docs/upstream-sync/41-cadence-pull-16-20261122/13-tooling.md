## 13. Tooling notes

- **Tools.** `docs/upstream-sync/pull7-tools/` (`sideresolve.py`, `hx.py`,
  `union.py`, `parsesweep.mjs`, `unmarkedsweep.sh`, `lostdecls.py`,
  `whatismissing.sh`), `docs/upstream-sync/pull9-tools/` (`remeasure.sh`,
  `classify.py`, `automerged.py`, `dangling.py`, `zones.py`), and this
  runbook's [`tools/`](tools/): `hunks.py` (hunk shapes of every conflicted
  file), `peek.py` (both sides of each hunk of one file, capped), `imports.py`
  (Loom-only files' imports against a merged tree), `overlap.py` (silently
  merged files with `loom` counts and churn), `composition.py` (what a diff's
  added lines are made of), `prdigest.sh` (Loom PRs against upstream's
  changes). Appendix A has the command lines.
- **Reading a conflict.** `python3 docs/upstream-sync/41-cadence-pull-16-20261122/tools/peek.py . <path> 40`
  in the merging worktree; `git show :1:<path>` (base), `:2:` (Loom), `:3:`
  (upstream); `git diff 3fa57b92a2 origin/main -- <path>` for Loom's whole
  delta in a file (the merge-base is an upstream commit, so Loom's side of a
  conflict is the entire fork delta there, not recent work); `git log
  --format='%h %s' 3fa57b92a2..a09738fb43 -- <path>` for the upstream commits
  behind a hunk.
- **Taking a side without touching the index** (lanes): `python3
  docs/upstream-sync/pull7-tools/sideresolve.py theirs <path>` (or `ours`)
  resolves every hunk of a file to one side in place; `git show :3:<path> >
  <path>` takes upstream's whole file. `git checkout --theirs` is the lead's.
- **Whitespace-blind views** for the eleven `Effect.scoped` test files:
  `git diff -w :1:<path> :3:<path>` and `git diff -w :1:<path> :2:<path>`.
- **`pnpm-lock.yaml`:** `git checkout --theirs pnpm-lock.yaml`, apply §5.4 to
  the manifests, then `vp i` until unchanged. Never hand-merge it.
- **`routeTree.gen.ts`** is generated by the TanStack Router plugin: start
  and stop the web build or dev server once in the merged tree (as pull 13's
  S1 did) and check that the diff adds upstream's three routes and keeps
  Loom's.
- **`vp run typecheck`** is the typecheck command (`effect-tsgo tsrs
  --noEmit` per package, cached per package). `vp lint <paths>` for a scoped
  lint. Pre-commit lints staged files and runs knip; merge commits are
  `--no-verify`.
- **The i18n lint run before the merged toolchain exists** used the target's
  rule sources with this worktree's oxlint (Appendix A). After `vp i`,
  `vp check` is the measurement.
- **The cockpit database** is `~/.t3/cockpit/userdata/statev2.sqlite` (4.73
  GB, WAL). Query it in place, read-only: `sqlite3
  "file:$HOME/.t3/cockpit/userdata/statev2.sqlite?mode=ro" "…"`. The one full
  copy is S3's: `sqlite3 -readonly <live> "VACUUM INTO
  '/mnt/fast/pull16/statev2.sqlite'"`, run with `bg_start`, deleted
  afterwards. The host `sqlite3` CLI predates trigram FTS5; use Node's
  SQLite to inspect FTS tables.
- **Disk.** `df -h / /mnt/fast` before every install and copy (§12).
- **Node.** `n` manages Node under `~/.n`; `n 26.13.1` switches every
  process started afterwards, the live cockpit included at its next restart
  (§5.3). `n exec 26.13.1 <cmd>` runs one command on it without switching.
- **Dev servers and verification.** `vp run dev` in this worktree uses its
  own `.t3` home; the dev-verify recipe (`docs/dev-site-testing.md`) and the
  `/preview` harness (`docs/web-component-preview.md`) are how S2b and S4
  take their screenshots. Stop what you start, by the PID you tracked.
