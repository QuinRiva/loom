### The §4.2 seams, tested at HEAD

Every upstream delegation mechanism reaches a thread through one of three keys:

- a parent `subagents` record with `origin === "app_owned"`;
- a child run's `delegatedTaskId`;
- `thread.forkedFrom.type === "node"`.

Loom never produces any of them. `makeLoomChildThread` writes `forkedFrom: null` (`Orchestrator.loom.ts:511`). `thread.spawn` accepts only `mcp`/`server` sources (`:1086`). `forkPrepare` emits only a `context-transfer.created`, never a thread update. `thread_fork` goes through upstream's `ThreadForkService`, which writes `forkedFrom: { type: "run" }` with `relationshipToParent: "fork"`. No Loom dispatch sets `delegatedTaskId`. The only producer of `type: "node"` is `provider-core/server/subagentProjection.ts` `makeSubagentChildThread`, used by the Claude and Codex adapters and the orchestrator's `delegate_task`. `provider-pi` never imports it.
