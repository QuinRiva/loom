- **On this project the dominant defect is excess, not absence.** This is a data-science prototype codebase: enterprise-grade engineering on throwaway analytics, scaffolding variables, single-use helpers and scope beyond the brief are the most frequent failures. For each, describe the simpler implementation that preserves the intended outcome. Pervasive or structural excess is must-fix.
- **Defensive code is a defect; the fix is removal.** The codebase trusts the happy path and wants bugs to crash loudly at the point of fault — a stack trace is the cheapest diagnostic there is, and an agent reads one perfectly well. A try/except, fallback value, silent default, `.get()` with a fabricated fallback, or re-validation of internal data converts a loud, locatable crash into a silent wrong answer. The only genuine boundaries are user input, external APIs, LLM outputs and files another system wrote; flag every other guard and recommend deletion — not an assert, not a comment.
- **Backwards compatibility does not exist here.** Migration or compat code for internal schemas, caches, logs or pipeline artefacts is a defect, not diligence — delete-and-regenerate is the default, and "kept for backward compatibility" in a diff is a review-stopping flag unless the human explicitly approved that specific shim. If a downstream script reads the old shape, the script gets updated; the shape does not get preserved.
- **Tests almost never earn their place.** In practice agent-written tests here fail only through their own brittleness; recommend deletion and say so plainly. The verification that counts is running the canonical entrypoint against real data — a green mock-heavy suite is not evidence the change works.
- Ask what business question the change serves and whether the codebase left behind is the simplest one that answers it. Do not recommend deleting useful behaviour merely because its repair crosses a package or repo boundary.
- Posture for the severity bar: a prototype under active watch where recovery is cheap, iteration speed is the currency, and every line of code is a liability — an excess-class defect above is must-fix.
