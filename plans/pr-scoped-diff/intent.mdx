# See exactly what one PR will contain, before it is pushed

**Goal.** "the current diff view isn't sufficient, particularly in the case of stacked PRs and an agent doing work on multiple PRs". "I want to be able to view what is included in a PR". For each PR a piece of work is preparing, you open that PR's changes and nothing else, measured against the branch it will be opened against. You do not need to know branch names, and it does not matter which branch the shared worktree has checked out.

Your graph-enrichment work on fathom-platform, as it stood on 24 Nov: two PRs built and not pushed, both cut from the branch of #4513, in one worktree.

**You'll know it works when.**

- In the orchestrator's thread, the Diff tab's left dropdown lists the PRs this work is preparing. Each shows its name, "not pushed" or its number, what it sits on, and its file count. The repository's other 650 local branches, which belong to other work, are not in it.
- You choose PE-2845 and see its 7 files. You choose PE-2844 and see its 16, with PE-2845 still checked out and nothing in the worktree moved.
- The Files list offers the same choice and marks the chosen PR's files. A marked file opens whole, side by side, as it does today. For a PR that is not checked out the file is read-only.
- Each change still names the thread that wrote it, so you can open or query that coder from the PR's diff.
- An agent renames a branch or amends its commit, and the list is right the next time you open it. On 24 Nov both branches were renamed and one commit amended.
- A PR cut from another unpushed PR shows its own changes only.

The three corrections, which hold whatever else is built:

- "Changes" on Automatic compares a branch cut from another PR's branch against that branch. PE-2845 reads 7 files with nothing chosen.
- The base picker appears only beside a comparison it affects. Today it sits beside "Since your message" and "Earlier" and does nothing there, which is what you were looking at when you asked "what should I select here?".
- The thread details card's Changes figure names the branch it is measured against without a hover. In your screenshot it read "Changes vs orig…" above a linked PR with a different count, and it would read the same after the first correction.

**Must not.**

- Change anything in the worktree to show a PR. No checkout and no stash: agents are working in it.
- Show a PR against a base it guessed without naming that base. When it cannot tell, it says so.
- Push, open or alter a PR. This is for reading.
- Make the Diff tab or the Files list slower to open, on this machine or over the relay.

**Approaches in play.**

- Read each PR from its commits (its branch against its base), not from the checked-out files. Wins if what you review is committed, which a PR offered for review is. It is the only approach that shows PE-2844 without touching the worktree, and for #4513 it gives GitHub's own count (4 files, +49 −11). _Recommended._
- Narrow today's combined diff to one thread's changes, with the "which thread wrote this" filter you already have. Wins if each PR is one thread's work and sits under the checked-out branch. Not enough alone: PE-2844 is not under the checked-out branch, the filter dims other threads' lines without removing them, and PE-2845's commit now names two threads.
- The agent writes a review document with the diff copied in, as the fathom orchestrator did for both PRs. Wins if you want a guided walk-through. It costs agent work per PR and again each time the PR changes: PE-2845's was rewritten a minute after its commit was amended. It also describes lockfiles, fixtures and version bumps in prose without showing them.
- Dropped: push each PR as a draft and read it on the Pull requests page. You said "I want to review befroe we create the pr".

**Decided.**

- "Create the ticket but I want to review befroe we create the pr". Review comes before anything is pushed.
- "I want to be able to view what is included in a PR". The unit is the PR, not the thread, the turn, or the whole branch against main.
- Already in place: the card's Changes figure follows the base you pick in the Diff tab. That was one of the two changes offered when you wrote "I don't understand why the diff numbers are so different". It arrived from upstream on 23 Nov, after your screenshot.
- This extends the October change-review brief, which gave you "Since your message" and the Files marks. Its "everything against the base branch" comparison becomes one comparison per PR; the rest of it stands.
- _Assumed:_ a line comment on a PR's diff goes where Diff tab comments go today, into the composer of the thread you are reviewing in. The card still offers the coder directly. Redirect if a comment should go straight to the thread that built the PR.
- _Assumed:_ a PR is its commits. Uncommitted changes show under the checked-out PR, marked as not yet committed. Redirect if they should be left out.
- _Assumed:_ before it has a title on GitHub, a PR is named by its branch and its first commit's subject.
- _Assumed:_ web and desktop. Redirect if you review PRs on your phone.

**Not doing.** Changes to the Pull requests page or its Code and Guide tabs. Pushing, opening, retargeting or rebasing a PR from this view. Drafting a PR's title or description here. Rewording any agent instruction: that is later work with its own review.
