# Upstream's nine PR and CI tools: the evidence says leave them off

Your read was "either these tools aren't useful for loom, or we should adapt loom to support them." Measured over the last three weeks, it is mostly the first. Your agents already do all nine jobs with `gh` from the shell, **about 850 calls**, with small outputs and almost no failures. I recommend **keeping all nine withheld**, this time as a decision with its evidence rather than a holding position, and closing the follow-up. The one build I can defend is a **pair of tools for answering review comments**, and its gain is small.

Upstream's own eval points the same way. On Sonnet both routes pass the same tasks and `gh` uses about 10% fewer tokens. The tools win only where `gh` is rate-limited, signed out, or the host is not GitHub, and none of those is Loom's situation.

<Callout tone="risk" title="Found on the way: in Loom's checkout these tools can aim at upstream's public repository">
  The tools pick their target repository from the git remotes and prefer the one named `upstream`, which in Loom is `pingdotgg/t3code`. What points them at `QuinRiva/loom` instead is a git setting that `pnpm ship` rewrites on every run, so on this VM they aim correctly today. On a fresh clone, an exposed create, reply or review tool would act on upstream's public repository under your account. The researcher confirmed this by running the resolver on Loom's real remotes with and without the setting; no call was made to GitHub. Any exposure has to pin the repository first.

## 2. The brief

**You'll know it works when** (under the recommended answers).

- A root, orchestrator or shipper thread started after the next deploy lists the same nine PR tools as today (link, watch, guides) and none of the new nine.
- `pnpm ship` is still how a Loom PR is opened and merged, and the shipper role and ship skill read as they do today.
- Row 10 of pull 16's follow-ups list reads as done and points at this brief, and the note beside the withheld list says why, so the next upstream pull does not redo the question.
- **Must not:** change any text an agent reads; expose any tool that writes to GitHub before the target repository is pinned.

**Approaches in play.**

- **Leave all nine off, as a decision.** Wins if the shell route keeps working as measured. _My pick._ Worth reopening if agents start answering review threads daily, if `gh` starts hitting rate limits, or if a project moves to a host `gh` cannot reach.
- **The review-comment pair:** `pull_request_read` and `pull_request_respond`. Wins if you want agents answering and resolving Copilot's review threads on fathom-platform PRs to become routine; today they reply and never resolve. It costs about a day of agent work: pin the repository, a sentence of role prose on replying under your name, an eval. It adds roughly 1 KB to each turn that loads them (estimated from the measured 5.0 KB for all nine), and two more Loom choices to re-check at every upstream pull.
- Dropped: the three read tools first, which is what the pull proposed. The reads work by shell and `ci_logs` has no edge.
- Dropped: the create and merge tools, with or without a server check. `pnpm ship` rebases, runs the checks, writes the trailers the deploy notice reads and deletes the branch; there is no point at which it could call the tools instead of `gh`. Outside Loom, `gh` is what the roles prescribe and it works.

**Decided.** "I think you're right that we should be done work like this after the merge lands, I think the issue in the past was that we were failing to do this for up work after the merge lands." This brief is that work.

- _Assumed:_ `pnpm ship` stays the only way an agent opens and merges a Loom PR, because nothing here replaces its checks; redirect if wrong.
- _Assumed:_ upstream's prompt text telling agents to prefer these tools over `gh` stays out of pi's prompt under every option, as the pull left it.
- _Assumed:_ the other tools pull 16 withheld (issue tools, feedback, theme, `send_to_user`) stay out of this goal. They are their own rows in the follow-ups list.

**Not doing.** Any change to `pnpm ship`. Any tool that merges, opens, edits or reviews a PR.
