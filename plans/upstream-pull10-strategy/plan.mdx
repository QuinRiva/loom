# Pull 10 strategy — a routine cadence pull with one structural prelude

Loom is a Pi-first fork of `pingdotgg/t3code`. Pull 9 re-platformed Loom's orchestration layer onto upstream's Orchestration V2 and landed on `main` with `docs/upstream-sync/UPSTREAM_BASE` = `9bd1d8009a` (2026-10-06). Since then upstream has shipped **554 commits** (`upstream/main` = `58d253231d`, 2026-10-12, v0.0.46-nightly) and Loom has merged ten PRs (#345–#368). This plan decides how to merge those 554 commits into Loom while keeping Loom's own features, following the sync doctrine in `docs/upstream-sync/05-strategy.md`.

**Done** means Carl has answered the form at the bottom, after which an orchestrator can write the runbook (`docs/upstream-sync/35-cadence-pull-10-v0.0.46-nightly-20261012.md`) and spawn the workstream in the section "Workstream graph" below without further design work.

<Callout tone="decision">
**The recommendation.** Pull 10 is a **routine single-pass cadence pull** in the shape of pull 8 (doc 27), not a phased re-platform like pull 9. The trial merge produces 104 conflicted files and 191 conflict markers — pull-8 sized — and upstream has not replaced anything Loom's orchestration layer stands on. What makes it more than a textbook pull is **one structural move upstream made** (every provider, Pi included, now lives in its own `packages/provider-*` package, so Loom's Pi hooks must move with it) and **four places where upstream now expresses functionality Loom built its own way** — those four are Carl's decisions, listed in the form at the bottom with my recommendation on each. Silence on a question accepts the recommended option.
</Callout>

## What changes for Loom's users, and what is at risk

Carl drives Loom all day through Pi threads, the workstream graph, goals and the task tree, MDX plans, and the sidebar. After pull 10 lands, the visible gains from upstream's 554 commits are:

- **Pi runs better.** Upstream fixed nine Pi-adapter defects Loom currently carries: workspace skills and slash commands are discovered again, selected skills load without dropping prompt text, Pi's native session rewinds are reconciled, extension approvals expire and cancel, thinking defaults are per model, tool images and structured results survive, shell exit codes and native abort outcomes are preserved, and known read-only T3 tools need no approval.
- **Find in thread.** Cmd+F over messages and plans in the open thread (upstream #10439), plus find-in-diffs — complementary to Loom's cross-thread content search, which stays.
- **Usage page.** Loads in under a second, filters by provider, and reads Pi's native sessions — upstream now ships its own Pi usage reader, which replaces the one Loom wrote (a decision below).
- **Pull requests.** Guided reviews, review guides that agents can write and read, quick actions per host, PR actions that confirm in place, and GitHub access through the API instead of the `gh` CLI.
- **Connections and permissions.** Scoped permissions (filesystem read/write, source-control write, preview control, diagnostics, environment administration), hosted agents (ChatGPT, Claude Code) signing in to the T3 MCP server over OAuth, and every MCP tool declaring who may call it.
- **Everyday web polish.** Reopen closed tabs, drag to reorder right-panel tabs, a thread-details shortcut, parent-thread breadcrumbs, grouped keybinding settings, block-level Markdown in the composer, MCP apps rendered inline, the browser preview running on the environment server, perf fixes to the timeline, diff panel and sidebar.
- **Platform.** Effect 4.0.2, typechecking with `tsc-rs`, Claude Haiku 5.5 in the catalogue (Loom already rolled this forward), and roughly eighty mobile commits that Loom takes verbatim because Loom carries nothing in `apps/mobile`.

What is at risk is the same list every pull puts at risk, and it is bounded: the Pi driver's Loom hooks (quota classification, session-id sanitising, steer stash, thread-fork cut, per-turn spend, the bundled patched `pi`), the workstream MCP toolkit's registration on the bridge, Loom's thread-mention chips, the file-chip and artefact viewer in previews, the Pi-first settings defaults, and the sidebar seams. Each is named in the zone tables below with its disposition.

## The structural prelude: Loom's Pi code moves into `packages/provider-pi`

This is the one piece of pull 10 that a three-way merge does not do for you.
