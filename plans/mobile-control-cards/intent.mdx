**You'll know it works when.** In an orchestrating thread, on your phone:

- A hand-back arrives as one compact card: a top line saying what arrived, then one entry per sub-thread with its name and verdict. It no longer fills several screens.
- You tap the top line and each entry opens to its excerpt. The exact text the agent received is one more tap away.
- You tap an entry and its report opens to read. The arrow beside it opens the sub-thread instead.
- Documents a report names show as chips under its entry, and a chip opens the document.
- A message that needs you (a rework round, an attention flag, a deadlock) is told apart from a routine one by its colour and label, as on web.
- Kickoff briefs, orchestrator steers and short notices stay the labelled bubbles they are today.
- **Must not:** change the text the agent received, since the card is only a way of showing it. Hide a message of a type the app does not know; that one shows its full text. Make a long thread slower to scroll. Card a message on the phone that web leaves as a bubble, or the reverse.

**Approaches in play.**

- **Web's card, redrawn for touch**, with everything web's card does: collapse, excerpts, raw text, open report, open sub-thread, document chips. The rule for which messages become cards and what each line says moves into the code web and phone already share, so the two cannot drift; only the drawing is new. _Your ask, as I read it, and the only approach left._
- Dropped: the collapse alone, with report and document opening as a second step. It was worth it only if opening a report on the phone were a project of its own, and it is not: the phone already opens files outside the project folder, reports included, over the tailnet and the relay alike.

**Decided.** "launch a hand off to build that too."

- _Assumed:_ web's card is the design, and the phone departs from it only where a narrow touch screen forces it. Three such departures are in the picture. An entry takes two lines, because sender, role, title and verdict do not fit on one. Tapping an entry opens the report, where web shows "Open report" on hover. A missing document shows struck through with no hover text. Redirect if you want something other than web's card.
- _Assumed:_ you see the card first, because no agent can run the phone app. This machine has no virtualisation, no other device host is set up, and the app has no web version. Before your look, agents test the card's logic against real hand-back messages from your live threads and test the taps in a simulated render, which proves the wiring and not the looks. Your look comes from an app built off the branch, about 21 minutes to build, published as a GitHub pre-release and installed over your daily app, before anything lands on main. Redirect if you would rather it ship and reach you through the normal update.
- _Assumed:_ cards start collapsed, as on web, including the old ones when you scroll back.
- _Assumed:_ Android and your one phone are what gets checked. The same code serves iOS and nobody looks at it there.
- _Assumed:_ nothing is built on the unshipped branch that adds a workstream view to the phone; this lands on main by itself.

**Not doing.** Any change to web's card or to what the control plane sends. The goal task tree on the phone, which is separate work.
