## 3. The policy underneath

Both PRs quote the same line as their licence, and it is the one thing to settle before the PRs: are plans committed history, or not?

### 3.1 Why the rule and the practice disagree

> Do not commit implementation plans, research notes, or agent scratch files. Keep temporary working material outside the worktree. `.plans/` is gitignored only as a safety net for legacy tooling.
> (`AGENTS.md:192`)

That bullet arrived verbatim with upstream PR #7665 (t3-code[bot], 20 Aug 2026) in the pull 7 merge on 21 Sep. It is upstream's policy for upstream's repo, which has no `plans/` directory. Loom committed plans before and after it: about 60 under `plans/` today, 75 files added across the three MDX directories in October alone, and loom's own `vite.config.ts` excludes `plans/**`, `recaps/**` and `explainers/**` from formatting with a loom comment calling them "product deliverables". PR #460 (`t3/audit-agentsmd`) rewrites `AGENTS.md` and leaves this bullet as it is, so fixing the rule is not already in flight. The `.plans/` safety-net clause is also stale in loom: `.plans/` is gitignored (`.gitignore:29`), yet 29 June-era files under it are tracked on `main`, and one of them is now the only file that still cites the goals plan #456 deletes.

### 3.4 Staleness, in three cases

- **`plans/sqlite-read-lane` and `-v2`.** The v2 is not a later design; it is the same decision re-authored as an MDX exemplar for a different reader. A thread would wrongly take v2 to mean v1 was superseded. Both are now stale against the code (v1 cites 8 source files, 5 gone), and the dead-code audit replaces loom's worker stack with upstream's `readerWorker`. A "superseded by" line fixes the v1/v2 confusion; "the lane design was later replaced" needs a status line written by whoever replaced it.
- **`plans/agent-started-thread-cue` and `-v2`.** v1 compares six treatments and recommends a combination; v2 recommends the left-edge rail, which is what shipped (`f41ba37530`). One line, `superseded_by: agent-started-thread-cue-v2`, fixes this completely.
- **`docs/design/workstream-review-gates.md`.** Live code cites it and #458 keeps it. It names 15 source files and 11 are gone, because the V2 port moved everything. The intent sections hold; the "where it lives" sections mislead. A header such as "describes V1 mechanics (pre pull 9); the intent in §1 to §3 holds; code is now in `orchestration-v2`" fixes most of it, and briefs already add the rest ("treat it as the map, but verify against the code").

A header fixes "which document is current". It does not fix "what drifted since"; the verify-against-code habit covers that and is already common in briefs. The marker is cheap only if it is written at the moment of supersession, so the convention has to live in the skill's "before drafting" step and its lint, not in a wish.

<Callout tone="decision" title="Recommended policy">
  **Plans, intent briefs, recaps and explainers written under the MDX skills are committed as dated snapshots of intent.** They are history, not documentation: not edited once done except for their status line; the current truth is the code plus `docs/internals` and `docs/architecture`, which link to the plan that established them. The storage is not the weak link; the habit of looking is.
