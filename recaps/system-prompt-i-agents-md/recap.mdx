# Loom's AGENTS.md is upstream's file with loom sections appended, and the upstream-sync policy is why it reads as it does

**3,974 words; about 1,000 of them are written for a human contributor to upstream T3 Code or state a rule that loom's own section then overrides.** Every loom thread of every role reads them every turn, at about 1.4K tokens. The audit proposed deleting them. What the audit did not know: each upstream pull's overlap review checks that "both supersede notes still name text that exists", because the file is deliberately kept as upstream's text plus loom's additions so the pull merges cleanly (`docs/upstream-sync/35-clean-overlap-review.md` row 1, `37-clean-overlap-review.md` row 24). The stated-then-overridden pairs are not an accident; they are the sync policy applied to a file that models read.

**The decision is therefore a policy one:** make AGENTS.md loom-owned (upstream's wording is no longer preserved; each pull's overlap review ports upstream's rule changes by hand, as it already does for roles and skills), or keep it byte-compatible and accept the 1,000 words. **I recommend loom-owned.** Upstream has changed this file in four of the last pulls, each time by a bullet or two, and the overlap review already reads the diff; porting a bullet costs less than every thread paying for the Theo note.

If loom-owned: five sections change (about 1,000 words out, 150 in), the rest stay as they are. The one factual assumption I could not settle is whether loom builds the mobile app; it decides one row of "Hit every surface".

**Protocol:** an item left undecided takes its recommendation. Section I0 is the policy decision; I1 to I5 assume it.
