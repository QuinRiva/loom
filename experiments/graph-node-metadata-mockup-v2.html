Workstream graph — node metadata redesign v2

v2 keeps everything that worked in v1 — the state-aware lifecycle (a running node is metadata-rich; a not-yet-run node stays clean and quiet) — and folds in the review feedback: the redundant activity phrase is gone, the provider + model shows as a tinted pill, the ⓘ button gets two labelled replacements to choose between, and the palette is recoloured so warm hues mean "you", not "waiting".

Priority order the board shows and the user cares about: 1 tool calls · 2 time since activity · 3 provider + model · 4 cost, plus the goal and the most recent turn action (the italic › … line) — which in v2 replaces the old generic phrases like live turn in progress.

1 · Same node across its lifecycle — metadata appears only when there's data

The always-on footer (⚒ tools · age) is the two highest-ranked, smallest facts, and exists only where the data does. v2 change: the node no longer carries the ⓘ affordance (see §4), and blocked is now a calm steel neutral — a passive dependency-wait, nothing to action — so it no longer shouts as loudly as a real call for the human.

4 · Replacing the ⓘ button — two options to choose between

You disliked the ⓘ dot. In both options a single click on the node still opens the thread; the ⓘ is gone from the node entirely. The question is where the secondary actions (history, report, stop) live. Both are mocked below, fairly — pick one.

Option AActions in the hover card

No affordance on the node. The hover card footer becomes real buttons — Enter (primary), History, Report. Power users also get middle-click on the node → History as a shortcut on top of this.
Trade-off: discoverable and zero node clutter, but actions live one hover away and the footer holds ~3 buttons comfortably.

5 · Recoloured palette — warm hues mean "you", not "waiting"

Today a passive blocked (waiting on upstream) is amber, and the real needs-a-human states are also amber/orange — so a dependency wait shouts as loudly as a genuine call for you. v2 moves blocked and the waits-on edge to a cool steel neutral, and reserves amber / orange / rose for the attention overlay only.

Before — warm = ambiguous

Amber does triple duty: a passive wait and a real call for you look identical.

After — warm = you

Cool = passive/waiting throughout; warm is reserved for "a human is needed".

blockedsteel — calm passive wait, nothing to action
waits-onsteel dashed edge — reads cool, like the wait
needs youamber — approval / input (reserved)
guidanceorange — needs guidance (reserved)
errorrose — stalled / error (reserved)

Unchanged (already unambiguous): in_progress sky, done emerald, yielded / gate violet, consult teal. Steel (#6d86a6) is deliberately bluer than planned slate (#94a3b8) and darker than ready cyan, so the three cool states stay separable at a glance.
