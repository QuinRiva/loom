Workstream graph — node metadata redesign

Pushing the board card's value into the graph the user actually lives in. The design is state-aware: a running node is metadata-rich; a not-yet-run node stays clean and quiet. Everything below is faithful to the live dark UI (#0d1117, the exact STATUS_STYLES colours, 146×56 nodes).

Priority order the board shows and the user cares about: 1 tool calls · 2 time since activity · 3 model · 4 cost, plus the goal (cut off today) and the most recent turn action (the board's italic › … line).

1 · Same node across its lifecycle — metadata appears only when there's data

The always-on footer (⚒ tools · age) is the two highest-ranked, smallest facts. It exists only where the data does: a running node carries a live footer; a planned/ready/blocked node has none, so it reads as a clean intent rather than a broken card full of dashes. Terminal nodes recede to 42% and drop the footer (their tool count moves to the on-demand card).

The 236px card can be tall (it's summoned deliberately), so it gains the missing board metadata as its own accented rows — tool calls, model, cost — the goal shows in full (the 3-line clamp is removed), and the most recent turn action gets its own footer. On a not-yet-run node the same card degrades honestly: the runtime rows read not started yet instead of zeros.
